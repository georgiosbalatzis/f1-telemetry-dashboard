# E09–E11 and Release B verification

Completed 2026-10-05. The optional article interaction is implemented on top of the saved-data contract. Existing article sources remain unchanged; authors opt in by using the telemetry figure marker. No deployment was performed.

## E09: standalone runtime

[interactive-entry.tsx](../../src/embeds/interactive-entry.tsx) exports `mount(container, savedData, { theme })`. It validates the plot-only payload, creates an open shadow root and a per-mount React root ID prefix, sizes from that figure's own host with `ResizeObserver`, and returns theme/unmount controls. Styles and the tooltip stay inside the shadow root. The dashboard and article use the same plot renderer. The runtime graph contains React, React DOM, Recharts and chart dependencies; it does not import the dashboard shell, API client, page navigation, presets or history code.

The standalone Vite build writes an entry manifest and its React/chart chunk dependencies to `dist-interactive`. `build:f1stories` assembles those files under `dist/interactive` with `/telemetry/` URLs. The same manifest/dependencies also resolve under the standalone `/f1-telemetry-dashboard/interactive/` base. `scripts/embed-interactive-check.mjs` consumes the emitted canonical artifact and exercises the actual lazy import path.

## E10: progressive article enhancement

The figure builder emits the four immutable static SVGs plus a separate plot-only JSON asset. It adds local data and runtime-manifest references to the `<figure>`; it emits no button. `setupTelemetryFigures` adds the control only when article JavaScript runs and the supported runtime references are present. Neither manifest, plot JSON nor runtime chunks are requested before a reader activates a figure. Concurrent activation on one figure is deduplicated; the manifest/runtime promise is reused across figures and cleared after failure so a later attempt can retry.

The saved picture stays visible during fetch and mount, then hides only after `mount` succeeds. A failed load leaves the image, caption and analysis link in place and exposes a short polite status. Returning to static calls `unmount` and restores focus to the control. One observer tracks the article theme and added/removed figures; removing a figure disconnects its runtime observer and reinserting it gets fresh controls. Runtime/data failures, removal/reinsertion and retry are covered by the article loader test.

An isolated article checkout ran `npm run build:public` successfully (3,163 files, 159.69 MB). A temporary marker fixture was then inserted only in that disposable worktree; the rebuilt and validated public artifact contained the referenced four SVGs and stripped JSON at the emitted article paths. The JSON was 10,805 bytes (1,428 bytes gzip) and omitted the image variants. That temporary fixture was not copied to the user's article checkout.

## E11: inspection and fallback behavior

The chart supports pointer/tap point choice without cancelling normal vertical gestures. A native range control supports arrow keys and Home/End, announces a polite text value only when the inspected point changes, and has a 44px target. Its readout includes driver/channel names and units; brake values use unsigned percentages. A collapsible semantic table exposes all saved point values. Description, source, caption and the analysis link remain in ordinary article HTML. Reduced-motion preferences are honored. Print hides the runtime and controls and forces the light static image.

## Release B browser and payload results

`node scripts/embed-interactive-check.mjs` passed on Chromium, Firefox and WebKit. Each run used two figures (speed and pedals), started with the article in dark mode, switched the host to light, changed viewport from 390px to 1440px and back, used arrow/Home/End inspection keys, restored a static figure, removed/reinserted the other figure, printed, and verified the URL, localStorage and host theme state. JavaScript-disabled pages retained both static images and had no controls. Each browser requested one runtime manifest, one entry plus its two dependency chunks, and the selected local data only after activation. There were zero OpenF1 requests.

Chromium evidence: [static no-JavaScript fallback](article-release-b/static-no-js.png), [interactive figures](article-release-b/interactive.png). In the 390px fixture, activation expanded the article content by about 386px because the interactive chart and its inspection controls replace the static image. This is user-triggered expansion; the static image remains in place until mount is ready. Chromium's standard layout-shift score across initialization and activation was 0.0166. Firefox and WebKit do not expose the same Layout Instability API in this check. Physical-device touch and hardware screen-reader testing were not performed; the browser check confirms the chart uses `touch-action: pan-y` without cancelling pointer events, and its native range control and semantic table provide non-hover inspection.

Measured compressed payloads:

- Interactive runtime and dependencies: 175,200 bytes gzip total (6,370-byte entry, 58,560-byte React chunk, 110,270-byte chart chunk), below the 300 KiB target.
- Baku review fixture plot-only JSON: 1,428 bytes gzip, below 150 KiB.
- Baku review fixture SVGs: 3,897–4,042 bytes gzip per variant, below 150 KiB. Both themes remain separate static assets and the interaction does not fetch them again.
- Local browser timing from activation click to mounted chart: 75–147 ms across the three engines. This is a local fixture measurement, not a field-network estimate.
