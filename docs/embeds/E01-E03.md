## E02: pure links and publication contract

`src/embeds/links.ts` provides:

- `buildDashboardLink(baseUrl, snapshot, options)`: pure URL construction with explicit base/anchor/theme/layout. `DashboardContainer` supplies its own current location in a thin adapter.
- `buildFigureAnalysisLink(baseUrl, scope, panelId)`: validated resolved scope, panel anchor and no `embed=1`.
- `parseLegacyEmbedLink(input, allowedBases?)`: exact origin/path allowlist, whitespace/entity normalization, duplicate required-query rejection and strict publication scope. Whole-tab URLs return `panelId: null` so a later composer can require editorial selection.

`src/embeds/contract.ts` provides v1 types, `validateFigureBundle`, `parseFigureBundle` and `serializeFigureBundle`. The contract bounds JSON to 5 MiB, SVG strings to 1 MiB each, points to 4096, drivers to four, dimensions to 4096px, and editorial fields to explicit lengths. It rejects non-finite values, unknown keys, unsupported versions, duplicate/reordered drivers, mismatched panel/plot/tab, invalid colours/dashes, unordered axes and inconsistent completeness. Missing values remain null. Brakes retain the existing negative plotting convention. Sample plots cannot advertise multiple complete drivers.

Drivers' full names/acronyms, source team colours and channel dash patterns live in `data.drivers`, in scope order. `context` holds GP and session labels, avoiding two copies of driver metadata. `data` discriminates `speed`/`pedals` and `progress`/`sample`; it holds only allowed plotted channels and saved guides. Optional `lineDash` means solid, while `brakeDash` is explicit. `provenance.drivers` stores original sample counts/status; missing drivers require acknowledgement. Captured times use the canonical `Date.toISOString()` form. Validation uses a fixed supported year bound (2023–2100), so stored historical bundles do not depend on a future reader's clock.

The canonical cross-repository contract fixture is [publication-v1.json](../../src/embeds/__tests__/fixtures/publication-v1.json). Its speed values are derived from the recorded Monza traces. Its four SVG values are **structural placeholders**, not production exports; complete figure export belongs to E04.

The article validator and byte-identical host fixture were added in E06; see [E04–E06 evidence](E04-E06.md). Incompatible schema changes require a new version and fixtures while retaining a v1 reader for published articles. No shared package or new dependency was introduced.

The v1 validator validates structure/semantics/size; it is not an SVG sanitizer. The publisher must additionally parse and allowlist XML and verify SVG/dimension consistency as specified in E06. Current code never injects bundle SVG into a page and exposes no publication ingestion UI.

## E03: shared plots and container sizing

`src/embeds/TelemetryPlot.tsx` renders either plot from explicit `FigureData`, width, optional height, theme and colour overrides. It uses saved guide metadata and inherited CSS variables from its containing scope, without reading the document root. It preserves the original speed range, pedal halves, unsigned percentage labels, line/area fallback, interpolation, missing-value behavior and disabled animation.

`ResponsiveTelemetryPlot` is the small dashboard adapter. It measures its own container with `ResizeObserver` and disconnects on unmount. Narrow/wide height and sample tick choices respond to this width, including split mode or a narrow column in a large viewport. `TelemetryTab` uses these shared plot bodies; its summary, panels, errors, menu actions and other charts remain under the existing dashboard shell. Other tabs retain their existing viewport-based axis decisions.

`src/embeds/plotModel.ts` projects only the required channels from the dashboard's existing data and constructs the shared legends, including distinct teammate/brake patterns. `useProgressAxis` now also exposes the existing inferred marks so the dashboard passes them to the shared renderer. The renderer does not recompute saved guides.

The renderer's imports contain no runtime dashboard container, API hooks, page hash/history or storage access. Its imports of API/filter types are erased by TypeScript. It does not import the global dashboard stylesheet. The scoped fixture-host CSS remains development-only; production saved image rendering is documented in E04–E06 evidence.
